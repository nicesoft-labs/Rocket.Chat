# Настройка Push для NiceSOFT

Rocket.Chat больше не использует облачные push-шлюзы Rocket.Chat. Все обращения к шлюзу перенаправлены на NiceSOFT (`https://ncsgp.ru`). Ниже приведены требования к серверу NiceSOFT, чтобы он корректно принимал и доставлял уведомления.

## Базовые принципы
- Шлюз принимает HTTPS-запросы от Rocket.Chat и доставляет их в APNs и FCM.
- Базовый URL: `https://ncsgp.ru`.
- Тайм-аут ожидания ответа Rocket.Chat: 60 секунд. При необходимости отправитель повторит запрос с экспоненциальной задержкой (1, 2, 4, 8, 16 минут) при ошибках 5xx.
- Rocket.Chat может передавать заголовок `Authorization: Bearer <token>`; сервер должен валидировать токен или игнорировать заголовок, если авторизация не требуется.

## Обязательные эндпоинты
Шлюз должен реализовать два эндпоинта, которые совпадают по схеме:

### `POST /push/apn/send`
Используется для устройств iOS/macOS.

### `POST /push/gcm/send`
Используется для устройств Android (FCM/GCM).

#### Тело запроса
```json
{
  "token": "string", // токен устройства APNs или FCM
  "options": {
    "uniqueId": "string",           // идентификатор сервера Rocket.Chat
    "from": "string",               // отправитель (например, имя сервера)
    "title": "string",              // заголовок уведомления
    "text": "string",               // основной текст
    "badge": 1,                      // (опционально) бейдж для iOS
    "sound": "string",              // (опционально) звук уведомления
    "notId": 123,                    // (опционально) идентификатор уведомления
    "contentAvailable": 1,           // (опционально) silent push для iOS
    "forceStart": 1,                 // (опционально) для запуска приложения на Android
    "topic": "string",              // (опционально) тема для APNs
    "apn": {
      "from": "string",
      "title": "string",
      "text": "string",
      "badge": 1,
      "sound": "string",
      "notId": 123,
      "category": "string"
    },
    "gcm": {
      "from": "string",
      "title": "string",
      "text": "string",
      "image": "string",
      "style": "string",
      "summaryText": "string",
      "picture": "string",
      "badge": 1,
      "sound": "string",
      "notId": 123,
      "actions": [ { "title": "Reply", "id": "reply" } ]
    },
    "query": { "userId": "string" }, // идентификатор получателя
    "token": "string",                // токен (дублируется для совместимости)
    "tokens": ["string"],             // список токенов (если обрабатывается несколькими девайсами)
    "payload": { "key": "value" },   // произвольные данные приложения
    "delayUntil": "2024-01-01T12:00:00.000Z", // (опционально) отложенная доставка
    "createdAt": "2024-01-01T12:00:00.000Z",
    "createdBy": "<SERVER>"
  }
}
```

#### Ответы шлюза
- `200 OK` — уведомление принято к доставке.
- `202 Accepted` — уведомление поставлено в очередь на отправку.
- `401 Unauthorized` — неверный токен авторизации; Rocket.Chat не будет повторять запрос.
- `406 Not Acceptable` — токен устройства больше невалиден; Rocket.Chat удалит его из базы.
- `422 Unprocessable Entity` — неверный формат данных; повторные попытки не выполняются.
- `429 Too Many Requests` — следует вернуть заголовки `Retry-After`; Rocket.Chat повторит с экспоненциальной задержкой.
- Любой `5xx` — рассматривается как временная ошибка; Rocket.Chat повторит попытку с увеличивающимся интервалом.

## Требования к доставке
- Для `POST /push/apn/send` необходимо формировать APNs notification payload на основе полей `title`, `text`, `badge`, `sound`, `category` и `payload`.
- Для `POST /push/gcm/send` требуется собирать FCM сообщение с полями `notification` (title/text/image/sound) и `data` (payload, notId, actions и т.д.).
- Шлюз должен возвращать детализированные логи ошибок, если доставка невозможна (например, истёк сертификат, неверный FCM key и т.п.).

## Настройка FCM на стороне NiceSOFT
1. Получить сервисный аккаунт Google Cloud для FCM (JSON-ключ).
2. Сохранить `project_id`, `client_email` и `private_key`; они используются Rocket.Chat для OAuth2 при прямой отправке, а шлюз может использовать те же данные для серверной отправки.
3. Разрешить доступ `https://fcm.googleapis.com/v1/projects/<project_id>/messages:send`.

## Настройка APNs на стороне NiceSOFT
1. Импортировать .p12 ключ и .cer сертификат в удобный формат (например, .pem).
2. Поддерживать выбор окружения: production `api.push.apple.com:443` и sandbox `api.development.push.apple.com:443`.
3. Включить поддержку `topic` и `category` для группировки уведомлений и действий.

## Требования к безопасности и мониторингу
- Все запросы только по HTTPS.
- Рекомендуется ограничивать доступ по исходящим IP Rocket.Chat или использовать mTLS.
- Логи должны содержать идентификатор `uniqueId` и `token` (хэшированно), чтобы отслеживать сбои.
- Метрики: количество успешных/ошибочных доставок по платформам, время обработки, количество удалённых токенов (ответ 406).

## Готовность к WebPush
Если потребуется поддержка WebPush, предлагается использовать ту же схему `/push/web/send` с телом запроса по аналогии с FCM, где поле `token` содержит endpoint браузера, а `payload` — данные уведомления.
